# Production migration ledger — project ilefwfpvphadsbptiaur
#
# The versions production's supabase_migrations.schema_migrations records for
# every migration created after the legacy baseline (20260729165052; see
# scripts/check-migration-drift.ts for why the split is frozen there).
#
# WHY THIS FILE EXISTS. Migrations here are applied through the Supabase API,
# which stamps its own timestamp rather than honouring the filename. A file
# that is not renamed to the version the recording assigned is drift forever,
# and the only tool that notices — `make check-db` — needs credentials, so it
# is outside `make check` and outside CI. Header comments were the record
# before this file, and by 2026-09-02 four headers said NOT YET APPLIED over
# migrations production had held for weeks, and three files carried versions
# production had never seen. A comment is not a record. This file is.
#
# THE RULES, enforced by scripts/migration-ledger.test.ts without credentials:
#   1. Every version listed under `applied` exists as a local migration file
#      with that exact version. If not, the file was applied under a different
#      version and must be renamed.
#   2. Every local migration file older than the newest `applied` version is
#      either `applied` or `pending`. An older file that is neither is the
#      trap: `supabase db push` will refuse it without --include-all, and
#      nothing else will say so.
#   3. `pending` names only files that exist and are NOT applied. Apply, then
#      move the line to `applied` (and rename the file if the recording
#      assigned a different version). A stale `pending` line fails the test.
#
# HOW TO UPDATE. After applying a migration, read the version production
# recorded (`supabase migration list --linked`, or the dashboard's migration
# history) and add it under `applied`. `make check-db` cross-checks this file
# against the live project and is still the release gate; this file lets CI
# catch the ordering trap the day it happens, not the day of the release.
#
# Format: one 14-digit version per line, sorted ascending within a section.
